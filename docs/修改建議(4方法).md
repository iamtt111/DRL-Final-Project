## 🛑 核心痛點分析：目前的盲點

1. **AWT 的陷阱**：`Nearest Car` 在早高峰的 AWT（平均等候時間）為 24.05s，略勝於 MAPPO 的 26.33s。如果圖表只強調 AWT，會顯得我們大費周章用 MAPPO 毫無意義。
2. **不對等的 Baseline**：`SARSA(λ)` 使用的是線性逼近（Tile Coding），在 16層樓、4部電梯且有多優先級的高維度環境中一定會遭遇「維度災難」。把它當作 MAPPO 的平行 Baseline 就像拿腳踏車跟跑車比，缺乏說服力。

## 🛠️ 具體修改行動 (Action Items)

### Action 1：補跑 `MaskablePPO` 的評估數據並更新 Report
我們在 `demo_app.py` 中已經實作了單智能體的 `MaskablePPO`。**請務必執行 `evaluate.py` 將 `MaskablePPO` 加入所有場景（Morning Peak, Evening Peak, Mixed Traffic, Disaster Crisis）的測試中**，並更新 `evaluation_report.md` 的表格。
* **目的**：這才是現代深度強化學習的真正對手，用來證明「多智能體（MAPPO）」優於「單智能體（PPO）」。

### Action 2：重構 Baseline 階層（4-Tier Storyline）
在報告或 README 中，請將我們的對照組劃分為以下四個演進層次，不要把它們扁平化：

* **第一層（傳統工業規則）：`Nearest Car`**
  * *價值*：作為 AWT 的極限基準線。
* **第二層（傳統表格式 RL）：`SARSA(λ)`**
  * *價值*：作為「方法論演進的消融實驗（Ablation）」。用來證明線性逼近器在複雜醫院環境會崩潰，突顯引入「深度神經網路（DNN）」的必要性。
* **第三層（單智能體深度 RL）：`MaskablePPO` (待補上)**
  * *價值*：作為現代 AI 基準。用來證明單一 Agent 控制 4 部電梯會面臨動作空間爆發，突顯引入「多智能體協同（Multi-Agent）」的必要性。
* **第四層（本專案終極方案）：`MAPPO`**
  * *價值*：透過 Centralized Critic 解決環境非平穩性，達成最佳的多目標權衡。

### Action 3：更新視覺化圖表重點 (Charts Generation)
* **捨棄單一的 AWT 長條圖**。
* **改繪製「Pareto 邊界圖 (Trade-off Scatter Plot)」**：X 軸為 AWT，Y 軸為 ERT。圖表將能清晰展示 `Nearest Car` 落在追求 AWT 的極端，而 `MAPPO` 是唯一能在兩者間取得最佳權衡的演算法。
* **增加「急診等待時間 CDF 圖」**：展示 MAPPO 能保證 95% 以上的急診都在極短時間內被響應（高穩定性），而 Nearest Car 會出現長尾效應。
